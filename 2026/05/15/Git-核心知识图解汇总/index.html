三、Git 工作流选择指南

Git 工作流选择指南

不同团队规模和项目类型，适合不同的 Git Workflow。

1. 集中式工作流

特点

  • 所有人直接在主分支开发
  • 结构最简单

适用场景

  • 个人项目
  • 学习练习
  • 小型团队（2～5 人）

2. 功能分支工作流

特点

  • 每个功能独立分支开发
  • 通过 Pull Request 合并

适用场景

  • 中小团队
  • Web / App 开发

3. GitHub Flow

特点

  • 基于 main 分支
  • 快速分支、快速合并、持续部署

适用场景

  • SaaS 产品
  • 快速迭代项目

4. Git Flow

特点

  • 包含 develop、release、hotfix 等分支
  • 发布流程规范

适用场景

  • 大型企业级项目
  • 多环境发布

推荐选择

团队情况 推荐工作流
个人项目 Centralized Workflow
中小团队 Feature Branch Workflow
持续部署项目 GitHub Flow
企业级项目 Git Flow

四、Git 三种回退方式对比

Git 三种回退方式对比

代码提交后出现问题时，Git 提供了三种常见的回退方式。

1. git reset

特点

  • 回到历史提交
  • 重写历史
  • 危险操作

适用场景

  • 本地撤销提交
  • 尚未共享的提交

2. git revert

特点

  • 创建一个新的“反向提交”
  • 不改变历史
  • 最安全

适用场景

  • 已推送到远程的提交

3. git checkout（现代用法为 git switch / git restore）

特点

  • 临时查看历史版本
  • 不修改历史

适用场景

  • 调试、对比历史代码

快速选择指南

需求 推荐命令
删除错误提交 git reset
撤销远程提交 git revert
临时查看历史 git checkout
